# Аналитика EsProfe: безопасная основа

## Зачем это нужно

Аналитика отвечает на продуктовые вопросы, а не становится видимым счётчиком на сайте:

- сколько людей приходит и из каких каналов;
- где они начинают обучение и где прекращают;
- сколько создают профиль и возвращаются к курсу;
- какие уроки, повторения и форматы действительно помогают;
- когда есть устойчивая аудитория для предложения дополнительных услуг.

Она не меняет учебные JSON-файлы, постоянные ID уроков и единый каталог. Поэтому один и тот же механизм обслуживает A1, A2, уроки с преподавателем и будущие тарифы.

## Два независимых слоя

| Слой | Что отвечает | Где смотрит владелец | Что не хранится |
| --- | --- | --- | --- |
| Посещаемость сайта | страницы, источники переходов, устройства, страны в агрегате | Cloudflare Web Analytics | имя, e-mail, ответы ученика, содержимое профиля |
| Учебный путь аккаунта | регистрация, начало/завершение урока, повторение, интерес к дополнительному сервису | закрытая серверная сводка Supabase | текст ответов, пароль, IP-адрес, e-mail в событиях |

Посещаемость не требует показа публичного счётчика: он не помогает ученику и часто искажает первое впечатление от школы.

## Постоянные имена событий

Имена ниже — контракт, а не текст интерфейса. Их нельзя переименовывать после появления данных; при расширении добавляется новое имя.

| Событие | Когда фиксируется | Минимальный контекст |
| --- | --- | --- |
| `account_registered` | профиль подтверждён и создан | `entry_point` |
| `account_signed_in` | успешный вход | `entry_point` |
| `course_opened` | открыт персональный маршрут уровня | `level` |
| `lesson_started` | ученик начал урок | `level`, `lesson_id`, `entry_point` |
| `lesson_completed` | урок завершён по правилам движка | `level`, `lesson_id` |
| `review_started` | открыт блок работы над ошибками | `level`, `lesson_id` |
| `review_completed` | блок повторения завершён | `level`, `lesson_id` |
| `teacher_lesson_started` | открыт урок с преподавателем | `lesson_id` |
| `trainer_opened` | открыт внешний тренажёр | `entry_point` |
| `upgrade_interest` | ученик сам запросил сведения о дополнительной услуге | `entry_point` |

`lesson_id` всегда берётся из общего каталога. Контекст допускает только короткие технические значения, например `home`, `route`, `search`, `profile`; в него нельзя помещать свободный текст, ответ ученика, e-mail или имя.

## Согласия и приватность

- Учебный профиль необходим для синхронизации прогресса; рассылка, обновления и аналитика — самостоятельные добровольные согласия.
- Без согласия на аналитику не создаются учебные события аккаунта. Отказ или отзыв согласия не закрывает доступ к обучению.
- События принадлежат только текущему `studentId`; браузер не может читать чужие события и не получает закрытую сводку.
- Детальная сводка доступна только через будущий защищённый серверный кабинет владельца. Публичный ключ Supabase и статический сайт не получают прав администратора.
- До включения Cloudflare Web Analytics на сайте должна быть опубликована понятная политика конфиденциальности и проверено требование согласия для выбранной конфигурации и юрисдикции.

## Порядок запуска

1. В Supabase после уже применённого `a1-cloud-sync.sql` один раз запустить `supabase/analytics-foundation.sql`.
2. Добавить отдельные добровольные переключатели согласий в профиль и только после этого подключить отправку событий из движков.
3. В Cloudflare включить Web Analytics для `esprofe.es`; ключ измерения хранится в конфигурации сайта, а не в учебных данных.
4. Подготовить закрытый кабинет владельца через серверный слой. Он читает только агрегированные представления, а не e-mail, пароли или ответы.
5. Перед запуском каждого нового события добавить тест, проверить четыре языка и обновить этот контракт при необходимости.

Первые показатели для решения о монетизации: рост уникальных визитов, доля «визит → регистрация», доля «регистрация → первый завершённый урок», возврат за 7/30 дней, завершение уроков и добровольный интерес к дополнительным услугам. Не использовать один показатель сам по себе.
