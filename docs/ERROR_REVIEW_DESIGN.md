# Сохранение занятия и личная работа над ошибками

Статус: проект алгоритма для личной проверки владельцем EsProfe. Не опубликован и не подключён к Supabase. Подготовлено 2026-10-13.

## Результат для ученика

- «Продолжить занятие» восстанавливает незавершённый урок и ответы.
- «Новая попытка» обнуляет табло и ответы текущей попытки, но сохраняет личные слабые места.
- «Новый ученик» переключает профиль; данные предыдущего ученика не копируются.
- Сохранение промежуточного занятия доступно после любого выполненного задания. Завершённый итог остаётся отдельной записью в lesson_attempts.

## Простой алгоритм

1. Ошибка создаёт или обновляет одно слабое место с постоянным lesson_id, question_id и учебным тегом. Не копируем текст задания, переводы, варианты ответов и аудио: они уже есть в JSON урока.
2. Исправление сразу после показа ответа не считается самостоятельным освоением. Оно разрешает идти дальше, но не удаляет слабое место.
3. В текущем занятии ошибочное задание возвращается после трёх других заданий. После конца основного банка оно попадает в доступный блок повторения.
4. В новой попытке добавляем не более одного задания из личных слабых мест на каждые три основных задания. До наступления срока повторения его не подмешиваем.
5. Самостоятельный правильный ответ при отложенном повторении переводит слабое место по ступеням: повторить через 1 день, через 3 дня, через 7 дней. Это стартовые настройки для проверки, а не обещание оптимальных интервалов для всех учеников.
6. Подсказка или немедленное исправление ступень не повышают. Несколько кликов в одном показе задания не считаются несколькими успешными повторениями.
7. Новая ошибка возвращает ступень к началу и назначает повторение в текущем занятии после трёх других заданий.
8. После успешного повторения через 7 дней слабое место помечается освоенным и убирается из обязательной очереди. Компактная отметка остаётся; при новой ошибке оно снова активируется. Основные упражнения остаются доступными.
9. Когда есть варианты задания для одного учебного тега, выбираем другой вариант того же правила. Если вариантов нет, повторяем исходное задание. Свободные примеры не оцениваем автоматически этим алгоритмом.

## Хранение

Предлагается отдельная student_lesson_state: одна запись на пару (student_id, lesson_id).

- progress: идентификатор текущей попытки, этап, позиции, выполненные ID, первая и последняя оценка ответа, черновики, собственные предложения, табло. Без бесконечной истории каждого клика.
- weak_items: только когда-либо ошибочные задания; для каждого question_id — тег, ступень, число ошибок, дата последнего самостоятельного повторения, срок следующего повторения, признак освоения. Для разбора можно сохранять последний ошибочный ответ с ограничением длины.
- revision и updated_at: защита от перезаписи более новой версии при работе с двух устройств.

lesson_attempts хранит отдельные завершённые итоги. Старые попытки не загружаются для подбора каждого следующего вопроса.

## Минимальная нагрузка

- Проверка ответа и выбор следующего задания выполняются в браузере; модели ИИ не вызываются.
- При открытии активного урока читаем одну запись его состояния. Историю результатов загружаем только при открытии истории.
- После каждого ответа немедленно сохраняем небольшое локальное состояние и помечаем его изменённым.
- При наличии изменений отправляем один облачный снимок не чаще раза в 60 секунд; также явно сохраняем по кнопке, при обычном выходе из урока и перед новой попыткой. Одновременно идёт только один запрос.
- В фоновой вкладке без новых ответов запросов нет. Реальное время, постоянный опрос сервера и отдельный запрос на каждый клик не нужны.
- Отправляем только состояние текущего урока. Для глобального кабинета используем компактные итоговые поля, а не все черновики всех уроков.
- При потере сети оставляем изменённый снимок локально, показываем «Сохранено на устройстве; ждёт синхронизации». Закрытие вкладки не гарантирует сетевую запись; не заявляем, что облако обновлено, пока сервер не подтвердил запрос.
- При подтверждённом сохранении снимаем флаг изменений. Повторная доставка того же снимка не удваивает счётчики: передаём актуальное состояние, а не команду увеличить их.
- Перед обновлением сервер проверяет текущего пользователя и ожидаемую revision. Конфликт двух устройств не разрешаем слепой перезаписью; локальные изменения сохраняем до восстановления согласованного состояния.

## Пример нагрузки

Условный ученик отвечает на 45 заданий за 30 минут. Запись после каждого ответа означает 45 запросов; запись только изменённого состояния с интервалом в минуту — не больше 30 фоновых запросов плюс явное сохранение. Быстрые серии ответов объединяются в один снимок, паузы не создают запросов. Экономия зависит от темпа занятия, а не от общего числа зарегистрированных учеников.

## Доступ и проверки

- RLS допускает чтение и запись состояния только при student_id = auth.uid(). Пароли и ключи администратора в данных урока отсутствуют.
- Потребуется отдельная SQL-миграция; текущие политики lesson_attempts не дают права на новую таблицу автоматически.
- Проверяем восстановление незавершённого урока, сохранение слабых мест после сброса табло, разделение учеников, отсутствие повышения ступени после подсказки, интервалы и ограничения очереди, повторную доставку, отсутствие сети и конфликт устройств.
- Сначала проверяем на футбольном уроке; общий модуль затем подключается к каталогу A1 с постоянными ID и учебными тегами.

## Что сейчас действует

Текущий проверочный файл хранит ошибки только внутри попытки на устройстве. Этот документ описывает следующий этап, а не уже работающую облачную историю ошибок.
