# Сохранение занятия и личная работа над ошибками

Статус: алгоритм согласован владельцем EsProfe 2026-10-13; ожидает реализации и проверки. Не опубликован и не подключён к Supabase. Подготовлено 2026-10-13.

## Результат для ученика

- «Продолжить занятие» восстанавливает незавершённый урок и ответы.
- «Новая попытка» обнуляет табло и ответы текущей попытки, но сохраняет личные слабые места.
- «Новый ученик» переключает профиль; данные предыдущего ученика не копируются.
- Сохранение промежуточного занятия доступно после любого выполненного задания. Завершённый итог остаётся отдельной записью в lesson_attempts.

## Простой алгоритм — уточнение по предложению преподавателя

Единица расписания — отдельное учебное занятие (сессия), а не календарный день, перезагрузка страницы или смена языка. Продолжение незавершённого занятия сохраняет его session_id; отдельное следующее занятие начинается явно.

1. Любая учебная ошибка попадает во временную очередь текущего занятия. Немедленное исправление после показанного ответа разрешает продолжить, но не является доказательством освоения.
2. Через три других задания проверяем то же правило самостоятельно: используем другой вариант, если он есть, иначе исходное задание. Несколько кликов и исправлений в одном показе считаются одной проверкой.
3. Долгосрочно запоминаем слабое правило, если на нём допущены две самостоятельные ошибки в текущем занятии (в разных заданиях или при отложенном повторении), либо отложенное повторение снова оказалось неправильным. Неразобранная первая ошибка в незавершённом занятии остаётся в его сохранённой очереди до проверки; она ещё не называется устойчивой.
4. Однократную ошибку, после которой ученик самостоятельно ответил правильно при отложенной проверке, не переносим в обязательное повторение следующих занятий. Компактный итог занятия может сохранять общее количество ошибок.
5. Повторные учебные ошибки ранжируем по неуспешной последней отложенной проверке, числу самостоятельных ошибок и давности повторения. Изображение ошибки и число исправляющих кликов не являются рейтингом сложности.
6. В следующем занятии предлагаем до трёх наиболее приоритетных слабых правил. При необходимости верхний предел можно повысить до пяти после проверки преподавателем; остальные слабые правила остаются в очереди.
7. После самостоятельного правильного ответа повторяем правило ещё через одно занятие. В новом контексте проверяем знание правила, а не запоминание одного ответа.
8. После двух успешных самостоятельных проверок в разных последующих занятиях правило помечается освоенным и убирается из обязательной очереди. Новая самостоятельная ошибка активирует его снова.
9. Если проверка вновь неправильна или выполнена с подсказкой, счётчик самостоятельных успехов не повышается; при неправильном ответе сбрасывается. Назначаем работу в текущем занятии и повторение в следующем.
10. Очередь не занимает больше одного задания на три основных задания. В конце занятия можно отдельно открыть оставшиеся ошибки; они не должны бесконечно прерывать основной урок.

### Что считается ошибкой

- Сохраняем постоянный учебный тег и ID задания: например, согласование по роду, множественное число или un/una. Не делаем вывод о правиле из произвольного свободного текста без надёжного проверяющего.
- Регистр, пробелы и допускаемая пунктуация нормализуются до проверки. Разрешённые форматы ответа (одно слово/полная фраза) не считаются ошибкой. Ошибки валидатора после исправления исключаются из учебных счётчиков.
- Описку отличаем от устойчивой проблемы по последующей самостоятельной проверке. Не объявляем любой неверный ввод грамматической проблемой автоматически; повторяющуюся орфографическую трудность сохраняем с отдельным тегом, если такой тег поддержан заданием.
- Свободные предложения остаются предметом проверки преподавателя; автоматическая проверка повтора изученных прилагательных не подменяет оценку грамматики.

## Хранение

Предлагается отдельная student_lesson_state: одна запись на пару (student_id, lesson_id).

- progress: идентификатор текущей попытки, этап, позиции, выполненные ID, первая и последняя оценка ответа, черновики, собственные предложения, табло. Без бесконечной истории каждого клика.
- weak_items: только когда-либо ошибочные задания; для каждого учебного тега — связанные question_id, число самостоятельных ошибок, число успешных проверок в разных занятиях, session_id последней проверки, номер следующего занятия для повторения, признак освоения. Для разбора можно сохранять последний ошибочный ответ с ограничением длины.
- revision и updated_at: защита от перезаписи более новой версии при работе с двух устройств.

lesson_attempts хранит отдельные завершённые итоги. Старые попытки не загружаются для подбора каждого следующего вопроса.

## Минимальная нагрузка

- Проверка ответа и выбор следующего задания выполняются в браузере; модели ИИ не вызываются.
- При открытии активного урока читаем одну запись его состояния. Историю результатов загружаем только при открытии истории.
- После каждого ответа немедленно сохраняем небольшое локальное состояние и помечаем его изменённым.
- При наличии изменений отправляем один облачный снимок не чаще раза в 60 секунд; также явно сохраняем по кнопке, при обычном выходе из урока и перед новой попыткой. Одновременно идёт только один запрос.
- В фоновой вкладке без новых ответов запросов нет. Реальное время, постоянный опрос сервера и отдельный запрос на каждый клик не нужны.
- Отправляем только состояние текущего урока. Для глобального кабинета используем компактные итоговые поля, а не все черновики всех уроков.
- При потере сети оставляем изменённый снимок локально, показываем «Сохранено на устройстве; ждёт синхронизации». Закрытие вкладки не гарантирует сетевую запись; не заявляем, что облако обновлено, пока сервер не подтвердил запрос.
- При подтверждённом сохранении снимаем флаг изменений. Повторная доставка того же снимка не удваивает счётчики: передаём актуальное состояние, а не команду увеличить их.
- Перед обновлением сервер проверяет текущего пользователя и ожидаемую revision. Конфликт двух устройств не разрешаем слепой перезаписью; локальные изменения сохраняем до восстановления согласованного состояния.

## Пример нагрузки

Условный ученик отвечает на 45 заданий за 30 минут. Запись после каждого ответа означает 45 запросов; запись только изменённого состояния с интервалом в минуту — не больше 30 фоновых запросов плюс явное сохранение. Быстрые серии ответов объединяются в один снимок, паузы не создают запросов. Экономия зависит от темпа занятия, а не от общего числа зарегистрированных учеников.

## Доступ и проверки

- RLS допускает чтение и запись состояния только при student_id = auth.uid(). Пароли и ключи администратора в данных урока отсутствуют.
- Потребуется отдельная SQL-миграция; текущие политики lesson_attempts не дают права на новую таблицу автоматически.
- Проверяем восстановление незавершённого урока, сохранение слабых мест после сброса табло, разделение учеников, отсутствие повышения ступени после подсказки, интервалы и ограничения очереди, повторную доставку, отсутствие сети и конфликт устройств.
- Сначала проверяем на футбольном уроке; общий модуль затем подключается к каталогу A1 с постоянными ID и учебными тегами.
